# Дизайн: расширение Chrome «Images-to-PDF»

**Дата:** 2026-06-04
**Статус:** утверждён, готов к плану реализации

## Цель

Расширение Chrome (Manifest V3), которое собирает изображения с текущей
веб-страницы и сохраняет выбранные пользователем картинки в один PDF —
каждая картинка на отдельной странице.

Проект учебный: чистые HTML/CSS/JS без сборки и npm, грузится «распакованным».
Комментарии в коде — на русском.

## Пользовательский сценарий

1. Пользователь на любой обычной веб-странице нажимает иконку расширения.
2. В попапе появляется сетка превью всех найденных картинок с чекбоксами.
3. Пользователь отмечает нужные (есть «выбрать все» / «снять все») и жмёт **Export**.
4. Расширение скачивает байты выбранных картинок, собирает PDF и инициирует
   скачивание файла `images-<сайт>-<дата>.pdf`.

## Архитектура и поток данных

```
popup.js  --1. "дай картинки"-->  content.js   (сбор всех <img> на странице)
popup.js  <--2. [{src,w,h,alt}]--  content.js

popup.js  3. рисует сетку превью с чекбоксами
popup.js  4. Export: список выбранных URL --> background.js

background.js  5. fetch(url) в обход CORS (host_permissions) --> хост картинки
background.js  6. <-- байты, кодирует в base64 data-URL
background.js  7. возвращает массив data-URL --> popup.js

popup.js  8. для каждой: <img> -> canvas -> JPEG -> jsPDF.addImage (страница на картинку)
popup.js  9. doc.save("images-<сайт>-<дата>.pdf") --> скачивание
```

### Почему сервис-воркер качает картинки

`content.js` и попап подчиняются CORS — изображения с чужих CDN часто не
скачать напрямую. Сервис-воркер расширения с `host_permissions` делает
кросс-доменные `fetch` свободно. Это каноничный приём MV3.

### Почему шаг через canvas

Превращение `<img>` → `canvas` → `toDataURL('image/jpeg')` в попапе:
- нормализует любой входной формат (PNG/WebP/GIF) в JPEG, который jsPDF
  гарантированно умеет вставлять;
- убирает проблему «tainted canvas», т.к. данные пришли как data-URL
  (свой источник), а не как кросс-доменный `<img>`.

## Структура файлов

```
images-to-pdf/
├── manifest.json          # конфиг MV3: разрешения, точки входа
├── src/
│   ├── content.js         # собирает <img> со страницы, отвечает на запрос попапа
│   ├── background.js      # сервис-воркер: качает байты картинок, кодирует в base64
│   ├── popup.html         # разметка попапа
│   ├── popup.css          # стили сетки и кнопок
│   └── popup.js           # оркестровка: запрос картинок, рендер сетки, сборка PDF
├── lib/
│   └── jspdf.umd.min.js   # библиотека локально (скачивается через curl при сборке)
├── icons/                 # 16/48/128 px (простые сгенерированные, либо дефолт Chrome)
└── README.md              # установка, использование, чек-лист тестирования (рус.)
```

## Ключевые решения и значения по умолчанию

- **Источник картинок:** только элементы `<img>` в v1. Фоновые CSS-картинки —
  возможное расширение в v2, в v1 не делаем (YAGNI).
- **Фильтр мелочи:** по умолчанию пропускаем картинки меньше 64×64 px по
  натуральному размеру (иконки, трекинг-пиксели). В попапе — переключатель
  «показать все».
- **Дедупликация:** одинаковые URL картинок схлопываются в один элемент.
- **Раскладка PDF:** лист A4 книжной ориентации, одна картинка на страницу,
  вписана с сохранением пропорций, по центру, поля ~10 мм, белый фон.
- **Имя файла:** `images-<hostname>-<YYYY-MM-DD>.pdf`.
- **Внедрение content.js:** не объявляем в manifest как постоянный
  content script (не висит на всех страницах), а внедряем по требованию через
  `chrome.scripting.executeScript({files: ['src/content.js']})` при открытии
  попапа. После внедрения `content.js` собирает картинки и отправляет их в
  попап через `chrome.runtime.sendMessage`.
- **Разрешения manifest:**
  - `activeTab` + `scripting` — внедрить content.js по требованию в активную вкладку;
  - `host_permissions: ["<all_urls>"]` — картинки бывают с любых доменов;
    в README отметить, что для публикации это сузили бы или вынесли в
    опциональные разрешения.
- **Без сборки/npm:** чистые HTML/CSS/JS, грузится «распакованным».
- **jsPDF:** версия 2.5.1 (UMD-сборка), кладётся локально в `lib/`. MV3
  запрещает удалённый код — только локальные файлы.

## Обработка ошибок

- **Нет картинок** на странице → сообщение «Картинки не найдены».
- **Картинка не скачалась** (403/CORS/битый хост) → пропускаем, не валим весь
  экспорт; в конце показываем «Добавлено N из M, не удалось K».
- **Спецстраницы** (`chrome://*`, Chrome Web Store, `view-source:`) → content
  script туда не внедряется; показываем понятное сообщение, что страница не
  поддерживается.
- **Долгая сборка** на больших страницах → индикатор прогресса при
  скачивании и сборке PDF; кнопка Export блокируется на время работы.

## Тестирование

Полноценные юнит-тесты требуют окружения Chrome, поэтому основной план —
**ручная проверка по чек-листу** (включается в README):

Основные сценарии:
1. Фотогалерея (много больших фото) — все картинки видны, экспорт корректный.
2. Новостная статья (текст + 2–3 картинки) — мелочь отфильтрована, нужное на месте.
3. Страница с кучей иконок — фильтр 64×64 работает, тумблер «показать все» работает.

Edge-кейсы:
4. Пустая страница / страница без картинок → «Картинки не найдены».
5. `chrome://extensions` → сообщение «страница не поддерживается».
6. Картинка с битой ссылкой / 403 → пропущена, отчёт «не удалось K».
7. Выбор «снять все» → Export неактивен / предупреждение.

Проверка результата: открыть полученный PDF, убедиться, что число страниц
равно числу выбранных картинок и пропорции сохранены.

## Вне рамок v1 (возможный v2)

- Фоновые CSS-картинки и `<picture>`/`srcset` (берём `currentSrc`, но без
  глубокого разбора).
- Несколько картинок на одну страницу PDF / настройка раскладки.
- Выбор ориентации и размера листа.
- Режим клика по картинкам прямо на странице.
- Сужение `host_permissions` через опциональные разрешения.
