# Дизайн: подготовка Images-to-PDF к Chrome Web Store

**Дата:** 2026-06-04
**Статус:** утверждён, готов к плану реализации
**Базовая версия:** расширение v1.0.0 (см. [2026-06-04-images-to-pdf-design.md](2026-06-04-images-to-pdf-design.md))

## Цель

Довести расширение до состояния, готового к загрузке в Chrome Web Store:
убрать широкое разрешение, починить отображение превью при большом числе
картинок, добавить английскую локализацию, собрать ZIP и подготовить тексты
листинга. После этого пользователю остаётся только загрузить ZIP в дашборд
под своим Google-аккаунтом. Версия поднимается до **1.1.0**.

## 1. Модель разрешений: точечный запрос по требованию

**Проблема:** `host_permissions: ["<all_urls>"]` показывает при установке
предупреждение «читать данные на всех сайтах» и осложняет ревью.

**Решение:**
- В `manifest.json` убрать `host_permissions`, добавить
  `optional_host_permissions: ["<all_urls>"]`. Оставить `activeTab` +
  `scripting` (их хватает, чтобы внедрять `content.js` в активную вкладку по
  клику — host-разрешения для этого не нужны).
- В `src/popup.js` в начале `exportPdf()` — **до первого `await`, пока активен
  жест пользователя** — вычислить домены выбранных картинок и запросить доступ
  только к ним:
  ```js
  const origins = distinctOrigins(urls);
  if (origins.length && !(await chrome.permissions.request({ origins }))) {
    setStatus(t('permissionDenied'), true);
    exportBtn.disabled = false;
    return;
  }
  ```
- Новый чистый модуль `src/lib/origins.js`, функция `distinctOrigins(urls)`:
  возвращает уникальные match-паттерны вида `<scheme>://<hostname>/*`,
  построенные как `url.protocol + '//' + url.hostname + '/*'` — **без порта**
  (порт в match-паттернах недопустим, а `URL.origin` его включает). Пропускает
  `data:`-URL (им разрешения не нужны) и кривые URL. Покрывается юнит-тестом.

**Почему это работает:** открытие попапа и показ сетки идут через `activeTab`
и не требуют host-разрешений. Доступ к доменам нужен только сервис-воркеру для
скачивания байтов — и просится ровно в момент экспорта, точечно. После выдачи
разрешение сохраняется (повторный экспорт на тот же домен не переспрашивает).

## 2. Фикс превью при большом числе картинок

**Корневая причина:** у grid-элементов по умолчанию `min-height: auto`, поэтому
ячейка не сжимается ниже intrinsic-высоты вложенной `<img>`. Большая картинка
растягивает плитку в высоту вопреки `aspect-ratio: 1/1` → вместо квадратов
получаются вытянутые полоски, превью почти не видно.

**Решение (CSS в `src/popup.css`):**
- `.cell` — оставить `aspect-ratio: 1 / 1`, добавить `min-height: 0`.
- `.cell img` — `position: absolute; inset: 0;` (вынуть из потока, чтобы
  картинка не управляла высотой ячейки) + `object-fit: cover` (плитка
  заполняется целиком, изображение легко узнать).
- Сетку сделать адаптивной и компактной:
  `grid-template-columns: repeat(auto-fill, minmax(96px, 1fr))` — при 181
  картинке влезает больше плиток, всё аккуратно листается.

## 3. Английская локализация (i18n)

Через штатный механизм Chrome i18n:
- Каталоги `_locales/en/messages.json` и `_locales/ru/messages.json` со всеми
  пользовательскими строками.
- `manifest.json`: `"default_locale": "en"`, поля `name`/`description` через
  `__MSG_extName__` / `__MSG_extDescription__`. Английский видит международная
  аудитория; пользователю с русской локалью браузера Chrome автоматически
  подставит русский.
- Статические строки в `src/popup.html` помечаются `data-i18n="ключ"`; при
  загрузке `popup.js` проходит по ним и подставляет `chrome.i18n.getMessage`.
- Динамические строки в `src/popup.js` берутся через локальный хелпер
  `t(key, substitutions)` поверх `chrome.i18n.getMessage`.

**Набор ключей** (значения — en / ru):
- `extName`: "Images to PDF" / "Картинки в PDF"
- `extDescription`: "Collect images from a page and save the selected ones to a single PDF." / "Собрать картинки со страницы и сохранить выбранные в один PDF."
- `appTitle`: "Images → PDF" (одинаково)
- `showAll`: "show all" / "показать все"
- `selectAll`: "Select all" / "Выбрать все"
- `deselectAll`: "Deselect all" / "Снять все"
- `exportPdf`: "Export PDF" (одинаково) — счётчик `(N)` дописывается в JS
- `foundImages` ($count$): "Found images: $count$" / "Найдено картинок: $count$"
- `noImages`: "No images found." / "Картинки не найдены."
- `pageNotSupported`: "This page isn't supported. Open a regular http/https website." / "Эта страница не поддерживается. Откройте обычный сайт (http/https)."
- `readError` ($error$): "Couldn't read the page: $error$" / "Не удалось прочитать страницу: $error$"
- `permissionDenied`: "Access to the image sites was not granted." / "Доступ к сайтам картинок не выдан."
- `downloading` ($count$): "Downloading images: $count$…" / "Скачиваю картинок: $count$…"
- `buildingPdf`: "Building PDF…" / "Собираю PDF…"
- `noneAdded`: "Couldn't add any images." / "Не удалось добавить ни одной картинки."
- `doneAdded` ($added$, $total$): "Done: added $added$ of $total$" / "Готово: добавлено $added$ из $total$"
- `failedSuffix` ($count$): ", failed $count$" / ", не удалось $count$"

`src/popup.html` слегка перестраивается: кнопка Export содержит
`<span id="exportLabel">`, текст которой целиком формирует JS
(`t('exportPdf') + ' (' + n + ')'`).

## 4. Сборка ZIP

`tools/package.sh`:
- удаляет и пересоздаёт `dist/`, кладёт в `dist/images-to-pdf.zip` **только
  рантайм-файлы**: `manifest.json`, `src/`, `lib/`, `icons/`, `_locales/`;
- не включает `docs/`, `tests/`, `tools/`, `package.json`, `README.md`, `.git`;
- печатает содержимое архива для проверки.

`dist/` добавляется в `.gitignore`.

## 5. Ассеты для листинга

- **`PRIVACY.md`** — политика конфиденциальности: персональные данные не
  собираются; вся обработка локальна в браузере; единственные сетевые запросы —
  скачивание выбранных пользователем картинок ради вставки в PDF; нет аналитики,
  серверов и передачи данных; обоснование разрешений (`activeTab`, `scripting`,
  опциональный host-доступ к доменам картинок). Отметить: для дашборда нужен
  **публичный URL** — т.к. репозиторий приватный, варианты: публичный Gist,
  GitHub Pages или сделать репо публичным.
- **`STORE-LISTING.md`** — готовый текст: название, краткое описание
  (≤132 символов), полное описание, категория (Productivity), обоснование
  single-purpose и каждого разрешения (это спрашивают в дашборде), и
  **чек-лист скриншотов** (1280×800 PNG, минимум 1, что снимать: попап с сеткой,
  процесс выбора, результат-PDF).

## Обработка ошибок

- Отказ в разрешении (`chrome.permissions.request` → false) → сообщение
  `permissionDenied`, экспорт не падает, кнопка снова активна.
- Выбраны только `data:`-картинки → `distinctOrigins` вернёт пусто, запрос
  разрешений пропускается, сразу собираем PDF.

## Тестирование

- **Юнит (TDD, Node):** `distinctOrigins` — уникальность, формат `https://host/*`,
  пропуск `data:` и кривых URL. Остальные существующие тесты должны остаться
  зелёными.
- **Ручной ре-тест в браузере:**
  1. Перезагрузить расширение → при установке нет предупреждения «все сайты».
  2. Открыть страницу с многими картинками (как на скрине, ~180) → превью
     видны нормальными плитками, сетка листается.
  3. Export → системный запрос доступа к домену(ам) картинок → «Разрешить» →
     PDF скачивается.
  4. Повторный экспорт на тот же домен → без повторного запроса.
  5. «Отклонить» в запросе → мягкое сообщение, кнопка снова активна.
  6. Сменить язык браузера на английский (или проверить на en-локали) →
     интерфейс на английском.

## Вне рамок

- Создание аккаунта разработчика, оплата $5, загрузка ZIP и заполнение полей
  дашборда — выполняет пользователь под своим Google-аккаунтом.
- Каркас оплаты/монетизации (ExtPay и т.п.) — отдельная задача, не сюда.
- Реальные скриншоты (нужен запущенный браузер) — даём чек-лист, снимает
  пользователь.
